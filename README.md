# 30 Günde İngilizce

A self-study English course for Turkish speakers, from A2 to B1, as a single interactive web page: 30 chapters, one per day, each planned as five hours of focused work, with explanations in Turkish and recorded English audio for every dialogue line, every word and example sentence, every reading text and every example in the grammar.

- **Public site:** https://azizjonkasimov.github.io/english-b1-book/ (GitHub Pages, built from `index.html` on `main`)
- **Run locally:** `node serve.js`, then open http://localhost:8767

Sister projects on the same engine: [Deutsch in 30 Tagen](https://github.com/AzizjonKasimov/german-a1-book) and [Italiano in 30 giorni](https://github.com/AzizjonKasimov/italian-a1-book).

## What is in a day

Each day is 300 minutes: a warm-up that recycles the previous days (15 min), a dialogue with playback, comprehension questions and shadowing (45), 30–36 words with example sentences and a self-test mode (45), two or three grammar blocks with tables, spoken examples and a comparison with Turkish (60), four to six exercise sets with hidden answers and self-scoring (45), a 250–350-word reading with a glossary and questions (40), three speaking tasks (20), a B1 writing task with a model answer and a checklist (20) and a ten-item day quiz (10). A tip on learning strategy or English-speaking culture and an "I can now" checklist close the day. Each section heading has a timer button; the page also counts the day's studied time.

Days 7, 14, 21 and 28 are review days with mini tests and listening tasks; day 29 rehearses the Cambridge B1 Preliminary format; day 30 is the final test with a B1 self-assessment and a plan for what comes next. The appendix holds a grammar summary in Turkish, the irregular verbs, useful phrases by situation and the typical mistakes of Turkish speakers.

The dialogues follow Elif, a marketing specialist from Izmir who has just started work in London, her flatmate James, her colleagues Priya and Daniel, her American friend Tom, her landlady Mrs Taylor and her cousin Mert in Antalya.

Progress (days marked as done, time studied) is stored in the browser's localStorage under `e30.*` keys, so it does not clash with the sister books on the same origin.

## Audio

All spoken English was generated with Microsoft's neural voices (British: Sonia, Libby, Ryan, Thomas; American: Jenny, Andrew) through the `edge-tts` package, then joined into one MP3 per day (`audio/day1.mp3` … `audio/day30.mp3`, plus `audio/extra.mp3` for the start page and the appendix) with a cue map in `audio/cues.json`. The page plays the right segment with the Web Audio API. If a clip is missing or the audio cannot be loaded, the browser's own speech engine is used as a fallback.

To regenerate after changing any English text:

```
node tools/extract-texts.js                # collects every playable text into tools/texts.json
.venv/Scripts/python tools/gen_audio.py    # generates missing clips into tools/cache/ (needs internet)
node tools/pack-audio.js                   # rebuilds audio/*.mp3 and audio/cues.json
```

One-time setup for the second step: `python -m venv .venv && .venv/Scripts/pip install edge-tts`. Clips are keyed by voice and text, so only new or changed texts are generated. The generator sends 16 requests at a time (pass another number as its first argument); 16 made about 7 clips a second, against 4 a second with 8, and no request failed. All 30 days come to about 5,500 clips.

To check that every speaker button has a recorded clip, open the page, then run this in the browser console on any day: it lists the texts that would fall back to the browser's own voice.

```js
const cues = await fetch('audio/cues.json').then(r => r.json());
const h = location.hash.slice(1), g = /^day\d+$/.test(h) ? h : 'extra';
[...document.querySelectorAll('#main .say, #main .say-long')]
  .map(b => [b.dataset.voice || 'f2', VOICES.ttsText(b.dataset.say)])
  .filter(([v, t]) => !(cues[g] || {})[VOICES.key(v, t)]).map(([, t]) => t);
```

## Files

| File | Contents |
|---|---|
| `src/page.html` | Styles, the rendering engine, the start page and the appendix pages |
| `index.html` | Generated by `node build.js`: `src/page.html` wrapped as a complete document, for GitHub Pages or plain viewing |
| `data/day01.js` … `data/day30.js` | The 30 lessons, one file each |
| `data/appendix.js` | Irregular verbs, useful phrases, common mistakes |
| `data/voices.js` | Speaker-to-voice mapping, the spoken-text normaliser and the clip key function, shared by the page and the tools |
| `audio/` | Per-day audio and the cue map |
| `tools/` | The audio pipeline and the lesson checks (below) |
| `serve.js`, `build.js` | Local preview server and the wrapper build |
| `AUTHORING.md` | The lesson format, the Turkish style rules, the cast and the syllabus |

`src/page.html` is written as page content only, without `<!doctype>`, `<html>`, `<head>` or `<body>`, so that it can also be published as a Claude artifact page. Run `node build.js` after editing it to refresh `index.html`.

## Writing or changing a lesson

The lesson format, the language rules and the 30-day syllabus are in `AUTHORING.md`; `data/day01.js` is the worked example. Two checks keep the files consistent:

```
node tools/check-lessons.js          # every day: required fields, counts, minutes, HTML balance, language of each field, speakers, repeated words
node tools/check-lessons.js 5 12     # only those days
node tools/lesson-summary.js 1-6     # a compact summary (title, grammar, words, reading, writing) of a range of days
```

`check-lessons.js` exits 1 on any error; warnings do not fail. After changing English text, rerun the three audio steps above.
